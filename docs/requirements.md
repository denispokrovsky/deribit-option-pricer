# Требования {#requirements}

Статус: ✅ реализовано · ⏳ запланировано (сознательно не реализуется в текущей версии).

## Контекст

Deribit — крупнейшая биржа опционов на BTC и ETH. Особенности, определяющие требования:

- опционы **европейские**, базовый актив — фьючерс (форвард) соответствующей экспирации;
- биржа котирует опционы в **волатильности** (`mark_iv`) и в **монете** (`mark_price` в BTC — «инверсная» котировка);
- экспирация — 08:00 UTC в дату из имени инструмента (`BTC-27DEC24-60000-C`).

## Функциональные требования

| ID | Требование | Статус |
|----|-----------|--------|
| FR-1 | Рассчитывать цену европейского опциона по модели Black-76 в USD и в монете базового актива. | ✅ |
| FR-2 | Рассчитывать греки: delta, gamma, vega, theta. | ✅ |
| FR-3 | Находить подразумеваемую волатильность (IV) по рыночной цене; сообщать, если цена нарушает границы отсутствия арбитража. | ✅ |
| FR-4 | Разбирать имена инструментов Deribit (дата, страйк, тип, дробные страйки вида `0d625`). | ✅ |
| FR-5 | Пакетная обработка: читать котировки Deribit (CSV) из stdin, писать IV и греки (CSV) в stdout, ошибки — в stderr с номером строки. | ✅ |
| FR-6 | Позволять выбирать алгоритм поиска IV параметром командной строки. | ✅ |
| FR-7 | Получать снимок котировок с публичного API Deribit (скрипт на Python, без ключей). | ✅ |
| FR-8 | Сохранять результаты в SQLite и строить отчёты SQL: сверка с `mark_iv`, улыбка волатильности. | ✅ |
| FR-9 | Строить поверхность волатильности (интерполяция по страйку и сроку, SVI). | ⏳ |
| FR-10 | Получать котировки в реальном времени через WebSocket Deribit. | ⏳ |
| FR-11 | Поддерживать американские опционы и дивиденды. | ✖ не требуется: на Deribit их нет |

## Технические требования

| ID | Требование | Как проверяется |
|----|-----------|-----------------|
| TR-1 | C++20, сборка CMake ≥ 3.25, без зависимостей, которые нужно ставить вручную (GoogleTest и Google Benchmark скачиваются CMake). | CI |
| TR-2 | Целевая платформа — Linux (Ubuntu 24.04); компиляторы GCC и Clang, предупреждения = ошибки. | CI, матрица gcc/clang |
| TR-3 | Только консольный интерфейс: stdin/stdout/stderr и коды возврата (0 — успех, 1 — ничего не посчитано, 2 — ошибка аргументов). Без GUI. | тест `cli_rejects_unknown_solver` |
| TR-4 | Ядро расчётов не выполняет ввод-вывод и не зависит от формата данных Deribit. | ревью, структура `include/dp` |
| TR-5 | Модульные тесты на каждое публичное свойство ядра; сквозной тест CLI на реальном снимке Deribit. | `ctest` в CI |
| TR-6 | Воспроизводимый запуск в чистом окружении: Docker-образ собирается и работает в CI. | job `docker` |
| TR-7 | Документация API генерируется Doxygen и публикуется на GitHub Pages при каждом push в `main`. | workflow `Documentation` |
| TR-8 | Разработка с ИИ-агентом (Claude Code) по правилам из `AGENTS.md`. | `AGENTS.md`, `CLAUDE.md` |

### Требования к производительности

Измеряются бенчмарком `dp_bench` при каждом запуске CI (Release, GitHub-hosted runner).

| ID | Требование | Бенчмарк |
|----|-----------|----------|
| TR-P1 | Цена одного опциона — не более **1 мкс**. | `BM_Black76Price` |
| TR-P2 | Поиск IV — в среднем не более **5 мкс** на опцион и не более 1% неудач на типовой цепочке. | `BM_ImpliedVol<SafeguardedNewtonSolver>` |
| TR-P3 | Полная цепочка из 1000 котировок (разбор имени, IV, греки) — не более **50 мс**, т.е. обновление всей доски BTC-опционов Deribit (~900 инструментов) укладывается в один кадр 20 Гц. | `BM_PriceChainOf1000Quotes` |

### Точность

| ID | Требование | Проверка |
|----|-----------|----------|
| TR-A1 | Цена совпадает с эталонными значениями с точностью 1e-10 (относительно). | `Black76.MatchesReferenceValues` |
| TR-A2 | IV, найденная по нашей модели, совпадает с `mark_iv` Deribit в пределах 0,05 пункта волатильности для опционов не глубоко в деньгах. | `QuotePricer.ReproducesDeribitMarkIv`, отчёт SQL №1 |
